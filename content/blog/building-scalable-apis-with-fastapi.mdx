FastAPI has become my default choice for Python APIs. It's fast, the DX is excellent, and the automatic OpenAPI docs alone save hours of back-and-forth with frontend teams. But the getting-started examples only scratch the surface.

Here's what I've learned building APIs that actually have to run under load.

## Why async matters

FastAPI is built on Starlette and supports `async/await` natively. If your handlers do any I/O — database queries, HTTP calls, file reads — making them async lets a single worker handle thousands of concurrent requests without blocking.

```python
from fastapi import FastAPI
import httpx

app = FastAPI()

# Bad — blocks the event loop during the HTTP call
@app.get("/sync")
def get_data_sync():
    with httpx.Client() as client:
        response = client.get("https://api.example.com/data")
    return response.json()

# Good — yields control while waiting
@app.get("/async")
async def get_data_async():
    async with httpx.AsyncClient() as client:
        response = await client.get("https://api.example.com/data")
    return response.json()
```

The rule: if you're calling async libraries (asyncpg, httpx, aioredis), use `async def`. If you're calling sync blocking code (SQLAlchemy sync, file I/O), use a regular `def` — FastAPI runs these in a thread pool automatically.

## Dependency injection

FastAPI's `Depends()` system is one of its killer features. It lets you compose reusable logic — auth, database sessions, pagination params — without cluttering your route handlers.

```python
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials

app = FastAPI()
security = HTTPBearer()

async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(security),
) -> dict:
    token = credentials.credentials
    user = await verify_jwt_token(token)  # your auth logic
    if not user:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid token",
        )
    return user

@app.get("/me")
async def get_profile(current_user: dict = Depends(get_current_user)):
    return current_user
```

Dependencies can depend on other dependencies. FastAPI resolves the whole graph, caches per-request, and handles teardown via `yield`.

```python
from sqlalchemy.ext.asyncio import AsyncSession
from database import async_session_factory

async def get_db() -> AsyncSession:
    async with async_session_factory() as session:
        yield session  # session is closed automatically after request

@app.post("/items")
async def create_item(
    item: ItemCreate,
    db: AsyncSession = Depends(get_db),
    user: dict = Depends(get_current_user),
):
    ...
```

## Request validation with Pydantic

FastAPI uses Pydantic v2 for validation. Define your schemas with type hints and let the framework handle parsing, validation, and error responses.

```python
from pydantic import BaseModel, Field, field_validator
from typing import Optional
from datetime import datetime

class ItemCreate(BaseModel):
    name: str = Field(..., min_length=1, max_length=100)
    price: float = Field(..., gt=0)
    tags: list[str] = Field(default_factory=list)
    published_at: Optional[datetime] = None

    @field_validator("tags")
    @classmethod
    def normalize_tags(cls, tags: list[str]) -> list[str]:
        return [t.lower().strip() for t in tags]
```

If the request body doesn't match, FastAPI returns a structured 422 with field-level error messages automatically. No manual validation code needed.

## Structuring a larger app

Flat `main.py` files don't scale. Here's a structure that works for production services:

```
app/
├── main.py           # App factory, middleware, startup events
├── routers/
│   ├── items.py
│   └── users.py
├── models/           # SQLAlchemy models
├── schemas/          # Pydantic request/response schemas
├── services/         # Business logic, separate from HTTP concerns
├── dependencies.py   # Shared Depends() functions
└── database.py       # DB engine, session factory
```

```python
# main.py
from fastapi import FastAPI
from routers import items, users

def create_app() -> FastAPI:
    app = FastAPI(title="My API", version="1.0.0")
    app.include_router(items.router, prefix="/items", tags=["items"])
    app.include_router(users.router, prefix="/users", tags=["users"])
    return app

app = create_app()
```

## Handling background tasks

For fire-and-forget work — sending emails, logging events, updating caches — use `BackgroundTasks`:

```python
from fastapi import BackgroundTasks

async def send_welcome_email(email: str):
    # heavy I/O operation
    await email_client.send(email, subject="Welcome!")

@app.post("/users")
async def register(
    user: UserCreate,
    background_tasks: BackgroundTasks,
):
    new_user = await create_user(user)
    background_tasks.add_task(send_welcome_email, new_user.email)
    return new_user  # returns immediately, email sends after
```

For anything heavier — job queues, retries, scheduling — reach for Celery or a Redis Streams-based worker instead.

## What I'd do differently

The main thing I've learned: keep your business logic out of route handlers. Handlers should parse input, call a service function, and return output. The service layer handles validation rules, database operations, and external calls. This makes testing dramatically easier — you can unit test services without spinning up an HTTP server.
